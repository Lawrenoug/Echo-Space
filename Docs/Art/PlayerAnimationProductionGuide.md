# Echo Space 玩家帧动画重生图规范与 AI 提示词模板

本文档用于后续批量重生 `Echo Space` 主角的单体人物帧动画。

目标不是立刻拆武器层，而是先稳定产出一套“同一人物、同一比例、同一基线、同一透视”的统一角色动画。  
武器切换将在后续装备系统中通过替换武器模型实现，而不是在当前阶段把人物帧动画拆成身体层和武器层。

## 1. 当前制作原则

- 当前人物只保留一个主体角色，不做身体层 / 武器层拆分帧动画
- 所有动作必须共用统一画布尺寸、统一脚底基线、统一镜头角度
- 现实世界版与灵魂世界版必须是同一个角色，只是风格和材质表现不同
- 允许动作夸张，但不允许人物体型、头身比、手臂长度、武器长度在动作之间漂移
- 所有素材默认朝右出图，游戏内通过翻转实现左右朝向

## 2. 画布与对齐规范

### 推荐基础规格

- 单帧画布：`622 x 584`
- 基线：`Y = 584`
- 导出格式：`PNG`
- 背景：透明
- 镜头：严格侧视，轻微动态夸张，但不转成 3/4 视角

### 对齐规则

- 所有动作的“脚底接地线”必须落在同一条基线上
- 待机、跑步、攻击、防御、受击、处决都不能自行漂移整个人物重心
- 如果动作需要跃起、后仰、前探，仍然要保证角色主干比例不变
- 攻击动作允许武器前探，但不能通过放大整张人物来制造力量感

### 尺寸统一规则

- 头部大小在所有动作里保持一致
- 身体躯干高度保持一致
- 武器长度保持一致
- 手臂伸展角度可以变化，但臂长不能变化
- 冲刺、攻击、处决可以更有动势，但不能让角色看起来像换了一套体型

## 3. 动作清单与帧数建议

以下是当前项目最需要的一批动作。

| 动作 | 文件名片段 | 建议帧数 | 说明 |
|---|---|---:|---|
| 待机 | `idle` | 6 | 呼吸、布料轻摆、保持重心稳定 |
| 跑步 | `run` | 8 | 明确摆臂摆腿，脚步接地点清晰 |
| 起跳 | `jumpstart` | 3 | 起跳蓄力与抬身清楚 |
| 下落 | `fall` | 3 | 下坠姿态，不要和起跳混淆 |
| 普通攻击 | `attack` | 8 | 前摇、出手、命中、收招完整 |
| 防御 | `guard` | 1-3 | 稳定架势，可偏防守 |
| 弹反 | `parry` | 4 | 爆发快、动作利落、反馈强 |
| 受击 | `hurt` | 3 | 明显失衡感 |
| 死亡 | `dead` | 6 | 失力、倒下、结束 |
| 处决 | `execute` | 6 | 强终结感，收招明确 |

## 4. 世界版本差异规范

### 现实世界版

- 关键词：沉重、磨损、写实、金属、旧布料、实体感
- 主色建议：深蓝灰、铁锈橙、旧皮革棕、暗金属色
- 光效建议：极少量反光，不做强发光边

### 灵魂世界版

- 关键词：冷色、发光边缘、灵体、虚化、能量扰动
- 主色建议：幽蓝、冷青、紫辉、苍白高光
- 允许表现：
  - 边缘轻微发光
  - 轮廓碎裂感
  - 布料尾端更轻、更飘
- 不允许表现：
  - 同时出现两个人
  - 身体大面积透明到看不清动作
  - 做成卡通幽灵或 Q 版角色

## 5. 角色动作约束

### 待机

- 重心稳定
- 可以有轻呼吸和武器微晃
- 不允许每帧抖动过大

### 跑步

- 身体允许前倾
- 脚底接地点必须统一
- 不允许跑步帧整体放大或缩小

### 攻击

- 必须分出前摇、命中、收招
- 允许武器轨迹夸张
- 不允许通过拉长人物比例制造力量感

### 防御 / 弹反

- 防御更稳，弹反更短促
- 二者不能做成同一套姿势
- 弹反动作应更锐利，中心线更紧

### 受击 / 死亡 / 处决

- 受击要有明确失衡方向
- 死亡是失力塌陷，不是站立换表情
- 处决动作要有终结感，但仍然维持同一角色体型

## 7. manifest 规范

当前项目会读取 `Docs/Art/PlayerSpriteFrames/manifest.json` 中的 `scale` 字段。  
因此重生图时要遵守以下规则：

- 同一动作组内的所有帧使用同一视觉比例
- `scale` 只用于少量修正，不应用来掩盖动作本身画布不统一
- 如果某组动作需要明显不同的 `scale` 才能看起来正常，说明源图本身比例已经漂移，应先重做源图

推荐做法：

- 尽量让所有新动作在默认情况下 `scale = 1.0`
- 只有历史素材兼容时才使用非 `1.0`

## 8. AI 生成总提示词模板

下面这条是“总模板”，适合你后续给任意动作做统一约束。

```text
为 2D 横版动作游戏《Echo Space》生成单体玩家角色像素风帧动画素材。

硬性要求：
1. 角色只有一个主体人物，不拆分身体层和武器层。
2. 严格侧视图，默认朝右。
3. 所有帧必须使用统一角色比例、统一头身比、统一武器长度、统一脚底基线。
4. 所有动作保持同一角色，不允许不同动作之间体型变化。
5. 透明背景，适合导出为逐帧 PNG。
6. 风格为成熟、克制、偏冷峻的像素动作游戏，不要 Q 版，不要可爱化。
7. 现实世界版强调实体感与旧金属、旧布料；灵魂世界版强调冷色和发光边缘，但仍然保持人物可读性。
8. 动作夸张可以体现在姿态和武器轨迹上，不能通过整体放大人物制造力量感。

输出目标：
- 生成同一动作的一组逐帧图
- 每帧人物都对齐同一脚底基线
- 所有帧保持统一画布和一致透视
```

## 9. 动作专用提示词模板

### 待机 `idle`

```text
基于 Echo Space 主角设定，生成 6 帧像素风待机动画。
要求：
- 严格侧视，朝右
- 角色站姿稳定
- 只有轻微呼吸、布料摆动、武器微晃
- 不允许整体抖动过大
- 所有帧脚底基线一致
- 保持统一角色比例和武器长度
```

### 跑步 `run`

```text
基于 Echo Space 主角设定，生成 8 帧像素风跑步动画。
要求：
- 严格侧视，朝右
- 身体允许前倾，但人物整体比例不能变化
- 脚步接地点清晰，脚底基线统一
- 跑步时布料和武器可有跟随摆动
- 不允许某些帧突然放大、缩小或拉长角色
```

### 普通攻击 `attack`

```text
基于 Echo Space 主角设定，生成 8 帧像素风单手近战攻击动画。
要求：
- 动作分为前摇、出手、命中、收招
- 武器轨迹清晰，姿态有爆发力
- 不要通过改变角色身材比例制造力量感
- 所有帧统一脚底基线
- 角色朝右，透明背景
```

### 防御 `guard`

```text
基于 Echo Space 主角设定，生成 1 到 3 帧像素风防御姿态。
要求：
- 稳定、收紧、守势明显
- 动作应与普通待机区分开
- 武器与手臂形成明确防线
- 人物比例、武器长度、脚底基线保持一致
```

### 弹反 `parry`

```text
基于 Echo Space 主角设定，生成 4 帧像素风弹反动作。
要求：
- 比防御更短促、更锐利、更有爆发感
- 重心收紧，动作干净
- 不允许和攻击动作混淆
- 所有帧保持统一比例与统一脚底基线
```

### 受击 `hurt`

```text
基于 Echo Space 主角设定，生成 3 帧像素风受击动画。
要求：
- 明显失衡、后仰或收缩
- 角色仍然保持同一体型
- 不允许像换了一个角色
- 透明背景，统一脚底基线
```

### 处决 `execute`

```text
基于 Echo Space 主角设定，生成 6 帧像素风处决动作。
要求：
- 强终结感
- 允许姿态更夸张，但人物比例不能变化
- 武器动作应有明确落点
- 收招姿势清晰
- 所有帧统一脚底基线与统一透视
```

## 10. 推荐工作流

1. 先固定现实世界版的 `idle / run / attack / guard / parry`
2. 用同一比例和基线补完 `jumpstart / fall / hurt / dead / execute`
3. 现实世界版确认后，再按同一轮廓重做灵魂世界版
4. 导出后检查：
   - 同一动作帧间是否抖动
   - 不同动作是否尺寸漂移
   - 武器长度是否一致
   - 脚底基线是否统一
5. 最后再更新 `manifest.json`

## 11. 当前最重要的制作结论

- 先把主角重生图做统一
- 不要现在就拆帧动画武器层
- 后续武器切换交给装备系统和武器模型节点
- 当前人物动画的任务，是成为后面所有装备外观叠加的稳定“角色底座”
